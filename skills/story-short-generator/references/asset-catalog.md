# 资产目录（角色卡 / 场景卡 / 道具卡 / 风格锚点 / 片段 / 文本）

> 本 Skill 的**资产定义**集中在这里。SKILL.md 的 STEP 3 / 4 / 4.5 只写执行步骤与门控，形态规范以本文件为准。
> 结构借鉴同语料的 `film-assets` skill（角色 / 道具 / 环境三大类 + 子类型 + 生成要求表），并按本 Skill 的**视频生产**用途收窄——**凡是要进 `ref_nodes` 的资产，一律单视图单主体**。

## 1. 资产总表

| 资产 | 画布 carrier | 画布分组 | 库内 `type` | 形态规范 | 可否作 `ref_nodes` | 对应步骤 |
|---|---|---|---|---|---|---|
| **角色卡** | image | `character cards` | `character` | 单视图正面全身、纯色背景、零文字 | ✅ | STEP 3 |
| **场景卡** | image | `scene cards` | `scene` | 单视图环境、无人物、零文字 | ✅ | STEP 4 |
| **道具卡** | image | `prop cards` | **无 `prop` 类型**（见 §5） | 单件道具、单视图、纯色背景、零文字 | ✅ | STEP 4.5 |
| 风格锚点 | image | 任意 | `style` | 单张风格帧、零文字 | ⚠️ 实验性，未实测 | 可选 |
| 片段 | video | `shot clips` | `clip` | — | ❌ 视频不可作参考图 | STEP 7 |
| 文本 / 表格 | text / table | 各对应组 | `text` | — | ❌ | 各步 |

**库内 type 由插件定义**（`ASSET_TYPES = ['character','scene','style','clip','text']`），本 Skill 不新增类型。`kind` 由 type 推导：`character|scene|style → image`、`clip → video`、`text → text`。

## 2. 角色卡

**用途**：锁定角色身份（脸、发型、身材、服装、签名道具），是 r2v 镜头的身份锚点。

**子类型**：本 Skill **只用一种**——单视图正面全身。同一角色的**不同着装 / 形态状态分别建卡**（如「不穿宇航服 / 穿宇航服」「常态 / 变身态」），标题用「统一角色名 + 状态后缀」。

> `film-assets` 有 三视图 / 四视图 / 八视图 / 表情包 / 姿势组图 / 角色卡 等子类型；**那些都不适合本 Skill 的 `ref_nodes`**（多主体参考图在 `fast` 档必崩，见 [reference-image-contract.md](reference-image-contract.md)）。真需要多角度时**逐张单独生成**，分别占 `ref_nodes` 槽位。

**生成要求**

| 要求 | 说明 |
|---|---|
| 形态 | 单视图正面全身；平视平角（相机与腰部至胸部齐平），禁止俯拍仰拍；比例正常，不拉伸不压缩 |
| 文字 | **图内零文字**——不画角色名、不画视图标注、不画道具标签、不加水印 |
| 背景 | 浅灰或纯白纯色；无第二身体、无剪影、无镜像 |
| 风格 | 所选风格文件的**风格锁后缀 + 负向约束**必须追加 |
| 光线 | 柔和均匀（`pixar-3d` 影棚光；`cinematic-live-action` 自然光 + 真实光比） |
| 清晰度 | 目标审阅尺寸下脸、服装、姿势细节可读 |
| 一致性 | 每次重出**完整复用同一份已确认外貌描述**；记录 seed 以便同 seed 微调 |
| 比例 | **2:3 竖版，不继承影片比例**——显式传 `width`/`height`（`fast` 672×1024 · `balanced` 896×1344 · `quality` 1344×2016，均 32 对齐）。理由：继承影片比例时 16:9 影片会得到**横版全身卡**，人物在画面里占比过小，作 `ref_nodes` 的参考质量差 |
| 非人形角色 | 形态一律按「实测 prompt 铁律：形态正向构造」写**正向解剖清单**，禁止否定堆叠 |
| 批量 | 同类资产一次性批量生成 |

**自检（自检点 1）**：单视图 / 零文字 / 背景纯净无第二身体 / 与节点描述逐项一致 / 符合所选风格锁。不过不许弹「锁定」选项卡。

**命名与入库**：标题写「角色名 + 状态」，定位与不可改特征写进**节点标题与描述**（不进图内）。跨会话复用在画布点「入库」（用户人工操作），id 形如 `character:luna`。

## 3. 场景卡

**用途**：锁定环境（布局、光态、地标、氛围），是 r2v 镜头的环境锚点。

**形态**：**单视图环境**（一个机位视角）。需要多角度时**逐张单独生成**，不要拼成多格场景卡。

**生成要求**

| 要求 | 说明 |
|---|---|
| 形态 | 单视图环境；机位与视角写进节点描述 |
| 内容 | **只展示环境**——无人物、无人群、无剪影、无手、无脸、无角色客串 |
| 文字 | **图内零文字** |
| 地标 | 写明**连续性地标**（同场景跨镜必须保持屏幕位置的固定物体，如门框 / 中岛 / 邮筒）及其画面相对位置——供镜头表 `固定地标` 列直接引用 |
| 光态 | 写明主光 / 补光 / 轮廓光方向与色温（日景 / 夜景各一版） |
| 风格 | 所选风格锁后缀必须追加 |
| 比例 | **跟随画布 `aspectRatio`**（与影片同比例，便于直接当镜头参考；**不要**给它套角色卡的 2:3 竖版） |

**自检（自检点 2）**：零文字 / 无人物与剪影 / 与节点描述一致 / `固定地标` 真实存在且位置可读未被遮挡 / 符合所选风格锁。

**命名与入库**：标题「场景名 + 光态」；地标名与位置写节点描述。id 形如 `scene:bridge`。

## 4. 道具卡

**用途**：锁定**签名道具**（反复出现、承担叙事功能的物件）的形状 / 比例 / 材质 / 配色，避免逐镜只靠文字描述导致漂移。

**形态**：**单件道具、单视图、纯色背景**。

> ⚠️ `film-assets` 的道具模块默认是「摄影机位环绕多视图」（三视图 / 四视图）。**本 Skill 一律收编为单视图单件**——理由同上：多主体参考图在 `fast` 档必崩。真需要多角度时逐张单独生成、分别占槽位。

**生成要求**

| 要求 | 说明 |
|---|---|
| 形态 | 单件道具、单视图；透视与光影写进节点描述 |
| 内容 | 只画道具本身——无人物、无手、无脸、无人群、无剪影、无场景环境 |
| 文字 | **图内零文字** |
| 特征 | 形状 / 比例 / 材质 / 配色 / 磨损特征逐项写进节点描述 |
| 风格 | 所选风格锁后缀必须追加 |
| 背景 | 纯色（默认纯白） |
| 比例 | **1:1 方形**（显式传 `width`/`height`，如 `balanced` 1344×1344）——单件道具居中，方形最省画面 |

**自检（自检点 3）**：单件单视图 / 零文字 / 无人物与手 / 与节点描述一致 / 符合所选风格锁。

**是否建卡**：**可选**。只在道具是叙事关键且**反复出现**时才建卡并进 `ref_nodes`（每张卡占一个参考槽位）；单次出现的小道具写进镜头描述即可。**单镜 `ref_nodes` 数量 >2 的形态未实测**——加了道具卡就优先在 `balanced` / `quality` 档生成。

## 5. 已知限制：资产库没有 `prop` 类型

插件资产库的 `type` 只有 `character` / `scene` / `style` / `clip` / `text`（`lib/assets.js`）。所以：

- 道具卡**入库时只能选这三选一**：`character` / `scene` / `style`，**推荐 `scene`**（道具属于"环境中的物件"），id 形如 `scene:prop-<name>`。
- **后果**：`asset_list(type=scene)` 拿到的资产**不一定是环境卡**。Agent 必须用**节点标题与描述**确认它的真实语义，不要盲信前缀。
- 若用户不接受语义混用，道具卡就**只在会话内以画布节点复用**，不入库。

## 6. 跨类公约

1. **风格锁**：所有图片类资产生成时都必须追加风格后缀（**按产物取用 A / B / C 段**，见 [style-selection.md](style-selection.md) 的取用表）。**铅笔分镜图除外**（始终纯黑白线稿）。
2. **图片档位**：所有图片类资产（角色卡 / 场景卡 / 道具卡 / 铅笔分镜图）都用 **STEP 0 选定的图片档位**生成，并**显式传 `tier=`**，**默认 `quality`**。**尺寸口径分两条路**：**文生图**长边 `fast` 1024 / `balanced` 1344 / `quality` 2048（× 画布比例，32 对齐）；**参考图改绘**（`image.image2image`）**没有固定长边**，输出尺寸**跟随第一张参考图**按该档「参考图预算」等比缩放（32 对齐），显式宽高不参与 ⇒ 想改绘出大图，参考图本身不能太小。`balanced` / `fast` **只用于抽卡试构图**，其产物**不得直接锁定**——锁定前必须用选定档位重出定稿。理由：卡片是全程复用的身份 / 环境锚点，重出会连带重做镜头表、分镜与已渲片段，返工代价远高于图片档位的成本差。
3. **参考图形态与门禁**：所有要进 `ref_nodes` 的资产（角色卡 / 场景卡 / 道具卡）都受 [reference-image-contract.md](reference-image-contract.md) 约束——`fast` 档必须通过 G-ref 形态门禁。
4. **入库由用户人工完成**：AI **不调用任何入库动作**，只在锁定卡片时提示用户"想跨会话复用就点该卡的入库按钮"。
5. **重做纪律**：卡片重做后，下游（镜头表 `绑定` / `固定地标` 引用、分镜、已渲片段）必须改用**最新批准的卡片**；旧卡在画布上标记废弃。详见 SKILL.md「重生成与最新资产纪律」。
6. **同一角色的状态卡**：续接**不继承身份**——续接沿用上一镜画面与声音，**不保证沿用服装 / 妆容**；认人永远看参考卡。
